# 输入框发送后清除：执行与自检计划

日期：2026-11-01。用户要求 Codex 明确病因、制定计划，交给 OpenCode 执行；Codex 最小干预、最小验收，减少周用量。执行者使用一个 interactive MM-F 会话，负责实施、自检、本地交付；不再派生 agents。

## 事实、根因与边界

上轮用真实 StoreProvider + 有状态模拟后端，按原生存储的 revision 条件消费草稿，已复现：

1. `store.tsx` 发送前 flush 已保存快照，但原 600ms autosave 定时器没有取消，也不在执行时重新检查 lastSavedDrafts。慢发送中它仍以 changed=true 重复保存相同内容；后端 revision 前进，`src/storage/mod.rs` 的发送事务按旧 revision CAS 清除失败。消息照常落库；下次 conversation-changed 刷新会把旧草稿回填。对照的快速发送正常清空。
2. `loadConversation` 只有 selectionToken 与 conversation id 检查，没有同一会话内的请求顺序 / 发送清除代际检查。发送前读取的旧 draft，迟于成功清空返回，仍会覆盖空 composer。清除并不推进后端 draft_revision，因此仅按 revision 大小过滤不足。
3. `dispatchSend` 仅当普通 composer 的文本 / 附件与提交快照完全相等才清除。发送期间追加输入会保留整段，包含原发送前缀。这是防止丢失新输入的现有保护，截图不能证明具体命中哪一条。不要通过删前缀或发送即无条件清空来掩盖竞态。
4. 关联代码缺口：编辑发送也比较普通 composer；`composer/clear` 会同时清普通和编辑缓冲；`applyConversationDetail` 无条件覆盖编辑缓冲；flush 与 autosave 的迟到回复缺少统一失效边界；空草稿被 autosave 直接跳过。这些仅在影响本轮清除 / 草稿恢复时做必要修复，禁止无关重构。

本工作区已有大量未提交改动。保留全部既有改动，不 reset、checkout、stash、提交或 push。旧 plans 是背景，不执行旧任务。

## 必须保持的行为

- 普通发送成功：提交的文本与附件从当前 composer 消失；后续事件、迟到读写回复、切换离开再回来均不能复活已消费快照。
- 提交未被后端接受 / 门禁失败：原草稿和附件保留，提示正确；不能先清空再丢失失败内容。不要把成功后的 refetch 失败误报成发送失败。
- 提交期间有新文本、附件、编辑模式或分支选择：旧回执不能删除新内容，也不能清另一会话。不要截取文本前缀猜测哪些输入属于新消息。
- 编辑发送只消费对应 edit buffer，普通 draft 保持；编辑期间的新改动不被旧回执或 refetch 覆盖。取消编辑和重新选择会话正确。
- 草稿在空内容状态也能持久化，删除全部文字 / 附件后切换会话不能恢复旧草稿；区分真实新输入与重复保存。
- 保留 IME、Enter / Shift+Enter、附件、多模型 / 分支、Stop、费用与 Models 工具栏已有行为。无付费 API 请求。

## 实施顺序

1. 阅读 AGENTS.md、计划及当前 store/reducer/types、Composer、IPC 和后端 draft CAS。自行确认上述机制。优先修改前端；只有证明前端无法满足正确性时才改最小后端 / IPC，并记录理由。不要新增依赖或整套状态管理系统。
2. 添加能表现实际草稿内容、revision 增长和 CAS 消费的测试后端；可新建独立 composer 生命周期测试文件，避免扰动其他测试。使用 deferred promises 控制读写完成顺序，模拟原生 IPC 的渲染间隔。先验证关键回归在原实现失败，记录 red 证据，再修复。不要用固定 revision 的假后端证明 CAS 正确。
3. 将发送快照、自动保存和迟到读取放在一致的会话 / 模式生命周期中：
   - 发送前处理已排队与进行中的同内容草稿保存，避免同快照重复 changed=true。回调执行前重新校验，不仅在 effect 安排时校验。不能只忽略保存回复，因为它可能已写回数据库。
   - 自动保存、flush、切换会话保存之间不能乱序把已消费旧正文写回。需要时用有界的按会话写队列 / 代际；不能让无限挂起写阻塞所有会话。现有 flush 上限 5s，保留有界响应；超时后迟到写不能复活已发送内容。不要仅 setTimeout 隐藏问题。
   - 同会话 refetch 要识别旧请求，以及成功发送清除前发起的读取。旧草稿可被舍弃；消息 / streaming / usage 的权威更新仍正常。需要同时保护普通与编辑本地新输入。
   - 成功清除需按实际提交模式和目标核对快照，原子判断当前状态，避免 React stateRef 尚未重渲染造成误判。普通 / 编辑缓冲分别清除，普通草稿不能被编辑发送抹掉。
   - 若涉及 lastSavedDrafts / baseline / revision，分别确认它们代表的内容与模式；不能将编辑内容错误视为普通已保存内容。
4. 自检并只修复本轮失败。保留有价值的回归测试。不要弱化原测试，不能仅检查源码字符串或仅测试新 helper。
5. 检查自身 diff 后更新本地 dist：版本保持 0.2.3；运行 `scripts/macos_build.sh`，随后 `scripts/macos_release_check.sh`。本计划已授权顺序执行 release 构建，无需等旧计划中的其他 agent。不替换 /Applications 安装，不终止用户正在运行的应用，不读取 dist/data 与备份。
6. 写 `docs/COMPOSER_CLEAR_RESULT.md`：确定根因、最终修复、逐项真实验证结果和命令、红转绿证据、构建结果、未解决限制。不得把代码检查说成实机验证。
7. 清理本轮 target/、gen/、临时测试脚本 / 截图 / 日志 / profiles、临时进程；保留正式源码、回归测试、文档、assets 与 dist。截图永不提交；用户真实数据和其他任务文件保持。

## 自检矩阵（可以合并测试场景，避免重复慢等待）

| 场景 | 必须断言 |
| --- | --- |
| 普通文本 + 附件成功发送 | payload 正确；composer 与持久化 draft 均已消费；切换回来仍空 |
| 快输入立即发送，发送跨过 600ms | 无同快照重复版本增长；CAS 成功；后续刷新不回填 |
| 自动保存已开始再发送，保存回复乱序 / 延迟 | 不重复写旧内容；最终持久化状态与 UI 一致 |
| flush 超时及迟到完成 | 不无限卡死；成功后迟到保存不复活；失败时草稿仍在 |
| 发送前 get_draft 延迟到清空后返回 | UI 不回填；不能仅靠 revision 大小判断 |
| 同会话两个 refetch 乱序 | 旧快照不覆盖新状态；正常流式与费用刷新不受损 |
| 发送期间输入 / 更改附件 / 改分支 | 新内容完整保留并可持久化；旧回执不误删 |
| 发送期间切换另一会话再返回 | 另一会话草稿不被覆盖；原会话成功内容不复活 |
| 编辑发送，普通缓冲已有草稿 | 只清编辑快照；普通正文 / 附件保持；新编辑输入保留 |
| send 拒绝 / 门禁失败 / 成功但 refetch 失败 | 草稿保留语义与提示正确；成功不被误报失败 |
| 手工清空文字 / 移除最后附件后切换回来 | 持久化为空，无旧内容复活 |
| IME 与现有发送快捷键 | 原测试通过，无额外发送 |

命令：`cd frontend && bun install --frozen-lockfile && bun run typecheck && bun test && bun run build`。测试自身要明确覆盖上述时序，不能只靠原用例通过。若改 Rust，跑直接相关 Rust 测试；无改动不另跑全量 Rust 测试。本地打包与 release check 只在源码自检完成后执行一次，有实际失败再重跑。

读结果、只比较本轮 diff；抽查保存调度与迟到读取失效、普通 / 编辑清除隔离。独立重跑本轮回归测试和 typecheck 一次；确认 dist 与 release check 真实结果及 target 清理。发现明确缺陷才退回同一 oc 会话修复，不再启动另一模型全面复核。
